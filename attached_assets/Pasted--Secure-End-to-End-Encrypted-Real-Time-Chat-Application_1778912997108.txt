# Secure End-to-End Encrypted Real-Time Chat Application

## Project Goal

Build a browser-based real-time encrypted chat application where:

* users can sign up and log in securely
* messages are encrypted inside the browser before transmission
* backend server cannot read message contents
* only sender and receiver can decrypt messages
* encrypted messages are stored securely in database
* users receive messages instantly using WebSockets
* offline users receive stored encrypted messages after login

The system should work similarly to modern encrypted messaging platforms.

---

# Core Security Principle

```text
Encryption and decryption MUST happen only in the browser.
```

The backend server must NEVER see plain-text messages.

---

# Full System Architecture

```text
Frontend Browser
    ↓ encrypted messages
FastAPI Backend Server
    ↓ encrypted storage
MongoDB Database
```

# Complete Message Flow

# Step 1 — User Signup

Frontend generates:

```text
Public Key
Private Key
```

Using:

```javascript
crypto.subtle.generateKey()
```

### Public Key

Uploaded to backend/database.

### Private Key

Stored in browser IndexedDB.

---

# Step 2 — Start Chat

User A opens chat with User B.

Frontend requests User B public key from backend.

Backend fetches public key from MongoDB and returns it.

---

# Step 3 — Encrypt Message

User types:

```text
"Hello"
```

Frontend encrypts locally using recipient public key:

```javascript
crypto.subtle.encrypt()
```

Result:

```text
"x92#KaP!"
```

---

# Step 4 — Send Encrypted Message

Frontend sends ciphertext through WebSocket connection.

Example:

```text
"x92#KaP!"
```

---

# Step 5 — Backend Routes Message

Backend receives encrypted text.

Backend:

* checks recipient
* checks online status
* forwards encrypted data

Backend CANNOT read message.

---

# Step 6 — Offline Message Handling

If recipient offline:

Backend stores encrypted ciphertext in MongoDB.

---

# Step 7 — Receive Message

Recipient browser receives encrypted ciphertext.

Frontend loads recipient private key from IndexedDB.

---

# Step 8 — Decrypt Message

Frontend decrypts locally:

```javascript
crypto.subtle.decrypt()
```

Result:

```text
"Hello"
```

Message displayed in UI.

---

# Recommended Security Rules

# MUST DO

✅ Encrypt messages before network transmission

✅ Store private keys locally only

✅ Use HTTPS

✅ Use password hashing

✅ Use JWT authentication

✅ Store only encrypted messages in database

---

# MUST NEVER DO

❌ Never store private keys on backend

❌ Never send plain-text messages to server

❌ Never decrypt messages on backend

❌ Never store passwords in plain text

---

# Recommended Future Improvements

# 1. Session-Based Encryption

Instead of encrypting every message directly with RSA:

Use:

```text
RSA/ECC
↓
Securely exchange AES session key
↓
AES-GCM encrypts chat messages
```

This improves:

* performance
* scalability
* modern security standards

---

# 2. Message Signing

Optional future feature:

Use digital signatures to verify sender identity.

Possible libraries:

* PyNaCl
* cryptography
